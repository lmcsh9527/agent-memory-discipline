# 问题定义（中文摘要）

> Agent Memory & Discipline System · M1 · 2026-08-20

## 一句话问题

LLM agent 在长会话中会"知道规则但不执行、有记忆库但不检索"——文本软约束在前 ~30% 会话后衰减归零，而现有记忆方案都是"被动库"（模型想查才查），缺一个"关键动作前强制查库"的硬机制。

## 实证（我们的部署环境）

1. 长会话（13,603 条消息 / 842 万字符）：开工规则脚本前 30% 执行率正常，之后 80–100% 归零——软纪律保质期 ≈ 会话前 30%。
2. 装插件任务：40+ 分钟反复试错（依赖放法试了 4 种、猜端口、踩权限/缓存坑），而不是先查已有机制/避坑文档——同一个"知道规则"的模型，关键时刻就是不执行。
3. 记忆漂移：基础设施事实（容器/服务位置）明明在记忆库里，用的时候没召回——不是检索失败，是根本没触发检索。

## 空白点

1. 现有方案几乎全偏编程场景；创作 / 多 agent 协作 / 部署运维 / 长对话纪律等通用工作场景稀缺。
2. **强制检索接入点缺失**（我们判断的核心创新点）：没有"高危操作前强制查避坑库"的硬机制——这是"有库不用"的根因。我们称之为 **"interception is retrieval"（拦截即检索）**。

## 请教社区的问题

1. 有没有在决策点**强制检索**的现成研究/实现（拦截钩子 + 强制查库）？
2. 除文本规则外，什么机制能让规则执行在 10 万+ token 会话中存活（要有数据）？
3. 有没有"纪律衰减 / 正确时机检索"的评测指标或基准（而非单纯检索质量）？
4. 非编程长周期工作流如何让 agent 跨天/跨周保持纪律？

## 我们的方向

三层架构——执行层（硬闸门：权限拦截 + 强制检索钩子）、注入层（保鲜：规则重注入 + 会话轮换）、记忆层（L0-L3 蒸馏 + 分级搜索 + "避坑知识库"）。

MVP = 避坑库（症状→根因→解法→关键词，≥10 条）+ 开工/高危前置强制检索 + 命中率可观测。成功标准：下一个部署类任务从 40 分钟反复试错 → 5 分钟内走对路径。
